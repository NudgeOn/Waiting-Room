# 0010 — 확정된 join과 조회 일정 등록의 결과 분리

상태: 구현·수정 전후 회귀 검증. 최종 이미지 수용 판정은 실행 기록을 따른다.

2026-09-10 단독 인원 검사에서 선행 join 제한과 대기표 저장이 끝난 뒤 수행하는
`register`가 남은 320ms 예산을 넘었다. 기존 코드는 조회 일정 등록 실패로 이미
확정된 join 응답을 503 또는 429로 바꿨다.

등록은 처음 조회할 시각을 미리 넣는 보조 작업이다. 공통 status 함수는 등록이 없으면
3~20초 분산 일정을 먼저 만들고 429를 반환하며, 허용되기 전에는 큐를 읽지 않는다.
따라서 성공적으로 저장·검증한 join은 이 보조 작업이 실패해도 원래 202와 같은 대기표
응답을 반환한다. 등록을 재시도하거나 대기 시간을 연장하지 않고 원래 context를 사용한다.

선행 join quota의 거부·장애는 여전히 저장 전에 차단한다. status·claim·heartbeat의
공통 제한과 epoch/fence 검사는 그대로다. 이 응답은 대기표이며 입장권을 발급하지 않는다.
정확한 join 재시도 응답, 기존 FIFO 순서, 데이터 보존 계약에도 변화가 없다.

회귀는 등록 오류/메타데이터 제한에서 기존 503/429를 재현하고, 수정 후 202·동일 재시도·
대기표 한 건을 확인한다. 필수 guard 장애의 저장·조회·입장 차단도 함께 확인한다.
