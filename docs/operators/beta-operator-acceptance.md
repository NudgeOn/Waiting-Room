# 로컬 Beta 운영자 수용 절차

상태: **실제 비개발 운영자 검증 미실행**. 자동 브라우저·API 검사를 이 결과로 대신하지 않는다.
기술 gate의 최신 결과는 [Beta 계획](../beta-plan.md)과 [후보 기록](../evidence/beta-20260910-m2-latency.md)을 따른다.
VoiceOver는 사용자 요청으로 이번 범위에서 제외했다.

운영자가 독립 테스트 설치와 가상 고객 경로를 사용한다. 진행자는 이미지/소스,
UTC 시각, 참여자의 역할과 성공·막힌 지점을 기록한다. 비밀번호·TOTP 비밀·복구 코드·
대기표·서명 입장권은 기록하지 않는다.

| 과제 | 관찰할 동작과 질문 | 통과 기준 |
| --- | --- | --- |
| 새 Room 준비 | 보호 경로와 유량을 정하고 로고를 올린 뒤 저장한다. 현재 실제 서비스에 적용됐는지 설명한다. | 초안 저장과 배포를 구분하고, 배포 상태/양쪽 ACK에서 적용 여부를 찾는다. |
| 입장 시작·일시정지 | 화면 설명을 보고 HOLD와 AUTO를 선택한다. 이미 입장한 고객에게 미치는 영향을 설명한다. | HOLD는 새 입장 배정을 멈추고 기존 입장권은 유지한다. AUTO는 검토한 제한 안에서 FIFO로 배정한다. |
| 안전 종료와 보호 해제 | 안전 종료를 실행하고 종료 대기 이유를 찾는다. 즉시 OFF와 차이를 설명한다. | 안전 종료는 신규 대기를 막고 남은 고객을 처리하며 종료 조건을 확인한다. OFF는 고객 경로의 보호를 해제하는 별도 명령임을 안다. |
| 고정 테스트 실행 | Traffic Lab의 Quick 20, Smoke 1K를 실행하고 결과·실패·감사를 찾는다. | 실행 상태와 결과를 구분하고, 결과가 고객 원본의 자동 유량 변경을 뜻하지 않음을 설명한다. |
| 장애·복구 이해 | 준비된 복구 대기 상태를 보고 영향과 재개 조건을 설명한다. | 안전 대기 시각 이후에도 검증이 필요하며, HOLD 확인 뒤 명시적으로 AUTO를 선택한다. epoch 교체가 기존 대기표·입장권을 무효화함을 안다. |
| 좁은 화면·키보드 | 320px 화면과 키보드로 Room 선택, 저장, 운영 상태 확인, 대화상자 취소를 수행한다. | 내용·오류·포커스를 놓치지 않고 수행한다. 자동 axe 결과와 사람의 사용성 결과를 별도로 기록한다. |

진행자는 정답을 먼저 알려주지 않고 화면의 용어·설명을 사용하게 한다. 설명을 듣고 성공한
경우에는 최초 수행을 통과로 바꾸지 않고, 막힌 문구와 보조 후 결과를 따로 남긴다.
재시도는 현재 입력과 결과를 보존한 상태에서 한다.

| 재검증과 변경 사항 | 미실행 |

판정 시 실제 관찰과 기술 gate를 함께 검토한다. 이 빈 절차 문서 자체는 Beta GO 증거가 아니다.
