# 페이지 주소와 대기 안내

새 대기열의 연결 단계에서 `https://shop.example.com/sale`처럼 보호할 페이지를
입력하면 원본 `https://shop.example.com`, 보호 경로 `/sale`, 상태 확인 경로
`/health`를 채운다. 상태 확인 경로는 실제 서비스에 맞게 수정한다.

대기실 주소는 기본적으로 `waiting.shop.example.com`을 제안한다. 다른 주소 직접
입력을 선택하거나 방문자 접속 주소를 수정해 별도 호스트를 사용할 수 있다.
호스트만 입력하거나 `https://queue.example.net` 형태로 입력한다. 대기실의 별도
포트·경로 매핑은 제공하지 않으며 원본과 같은 보호 경로를 사용한다.
페이지 URL의 계정·쿼리·fragment·인코딩/정규화가 필요한 경로는 자동 입력에서 거부한다.
기존 원본·호스트·경로의 개별 입력과 서버 검증도 유지한다.

이 기능은 기존 reverse proxy 설정을 쉽게 입력하는 기능이다. DNS 레코드나 인증서를
자동 발급하지 않는다. 대기실 호스트를 Gateway로 연결하고 HTTPS를 구성해야 한다.
입장 후에도 브라우저 주소는 대기실 호스트이며 Gateway가 원본 내용을 전달한다.
원본 URL로 이동하는 cross-domain 인증이나 원본의 직접 접속 차단을 대신하지 않는다.

새 대기열의 **입장권 TTL 기본값은 60초**다. DNS TTL이나 대기표 TTL이 아니다.
기존 저장 대기열은 변경하지 않는다. 새 대기열은 설치 계획의 입장 수·분당 입장
기본값을 사용하되 입장권 TTL은 60초에서 시작한다. 유량 시작값도 60초이며
운영자가 60~3600초 범위에서 수정한다.

## 방문자 순번과 예상시간

- 상태 조회에서 실제 Valkey 대기 인덱스의 순위에 1을 더해 `약 24번째`처럼 표시한다.
  뒤에 새로 들어온 방문자는 내 순번을 늘리지 않는다. 동시 입장·만료 정리와 조회
  시점 차이 때문에 대략적인 값이며 입장 자격 판정에는 쓰지 않는다.
- 최근 60초 promotion 수, 설정된 분당 입장 수, 입장권 수와 TTL·검증 여유시간에
  따른 처리율 중 작은 값으로 예상시간을 계산한다. 중심값의 75~150% 범위를
  `약 2~4분`처럼 표시한다. 최근 입장 이력이 없으면 계산 중으로 표시한다.
- HOLD/OFF에서는 입장 재개 대기를 안내한다. 연결 오류·만료 시 이전 순번과 시간을
  숨긴다. 성공한 다음 조회에서 다시 표시하며 실시간 카운트다운이나 SLA가 아니다.
- 새 대기열은 예상시간 표시가 기본으로 켜진다. 기존 대기열은 설정의
  **예상 대기시간 표시**를 켜고 저장·서비스 적용해야 한다. 순번은 항상 표시한다.
- 읽기 전용 부가 조회는 최대 100ms를 사용한다. 실패하면 순번·예상값을 생략하고
  기존 상태 응답을 유지한다. 대기표·TTL·입장 판단·Lua 함수와 저장 스키마를 변경하지 않는다.
- 최초 join의 재시도 응답은 그대로 유지한다. 현재 순번과 시간은 status에서만 제공한다.

`npm run test:admin-browser -- --grep 'Room draft|setup wizard'`,
`npx playwright test --config playwright.config.mjs`.
