# 대기 화면 로고

Room 생성의 **대기 화면** 단계 또는 기존 Room의 **설정 → 대기 화면**에서 로고를
선택한다. PNG·JPEG 파일은 16 KiB 이하, 가로·세로 각각 1~256px이어야 한다.
저장할 때 서버가 픽셀을 읽어 PNG로 다시 인코딩하며, 변환 결과도 16 KiB 이하여야 한다.
변환 후 한도를 넘으면 더 작은 이미지나 단순한 로고를 선택한다. SVG·GIF·외부 URL은
허용하지 않는다. 원본 파일명·메타데이터·추가 데이터·애니메이션을 배포하지 않는다.

선택 후 미리보기에서 확인하고 **초안 저장**한다. 파일 선택이나 초안 저장만으로 방문자
화면이 바뀌지 않는다. 기존 설정 배포 절차를 거쳐 Gateway와 Coordinator의 적용 응답을
확인해야 한다. **로고 제거 → 초안 저장 → 배포**하면 기본 화면으로 돌아간다.
잘못된 파일을 선택하면 오류를 표시하고 기존 선택은 유지한다.

로고는 별도 외부 저장소 없이 초안과 서명된 설정에 포함된다. 기존 PostgreSQL 저장,
24시간 명령 재시도, 감사 및 콜드 백업·복원 경로를 그대로 따른다. 저장 API의
`theme.logoImage`는 base64 PNG·JPEG를 입력받고 정리한 PNG만 응답한다. 생략하거나
빈 문자열을 저장하면 로고를 제거한다. 이미지 검사는 권한·CSRF와 기존 재시도 확인
이후 수행하며, 실패한 저장도 같은 키로 재시도하면 같은 거부 결과를 반환한다.

전체 설정은 기존 64 KiB 서명 봉투 한도를 유지한다. 초안 저장 시 모든 Room의 향후
복구 모드·epoch·revision 필드까지 공간을 확보한다. `CONFIG_CAPACITY_EXCEEDED`가
표시되면 로고나 문구를 줄여 다시 저장한다. 이미지별 한도 이내여도 전체 설정이 크면
거부될 수 있다. `INVALID_THEME_IMAGE`는 이미지 형식·픽셀·입력 또는 PNG 출력 한도를
벗어난 경우다. 두 경우 모두 기존 초안·배포 설정은 바뀌지 않는다.

Gateway는 검증된 설정의 PNG만 같은 호스트의 전용 경로로 제공한다. GET·HEAD만
허용하며 `image/png`, `nosniff`, `no-store` 및 제한된 CSP를 사용한다. 이미지 설정이
없는 기존 초안은 그대로 읽는다. 이 기능을 사용하기 전 Control·Gateway·Coordinator를
모두 같은 지원 버전으로 업그레이드한다. 로고 필드를 모르는 구형 이미지로의 다운그레이드는
지원하지 않으며, 이전 버전 복귀는 업그레이드 전 콜드 백업의 복원 절차를 따른다.
